# AI 模组语言文件翻译：计划，不属于本轮实现

## 是否值得做
值得。它与当前文本 AI 接口兼容，结果可以作为独立资源包启用、停用和分享，不必修改模组 JAR。先聚焦语言 JSON，比添加广泛的 AI 自动操作更有明确用途。

## 第一版范围
1. 从当前实例选择一个模组，列出其 assets/<命名空间>/lang 下可识别的 JSON 语言文件。
2. 选择源语言和目标语言；已有目标语言时优先只翻译缺失项，保留已有译文。
3. 展示条目数、待发送文本和大致用量；用户确认后，按批次发送给已配置的 AI。只发送语言条目，不上传整个 JAR 或游戏日志。
4. 允许简单术语表，用于统一物品、方块、机器、维度和专有名称。
5. 预览原文/译文，可逐条编辑、重试失败批次，再生成独立资源包 ZIP。
6. 按目标游戏版本生成 pack.mcmeta，并仅包含新语言 JSON。可选择放入该实例 resourcepacks；是否启用由用户决定。
7. 缓存已完成批次，中断后续做，避免重复请求费用。不自动重新付费请求。

## 必须处理的质量问题
- 键名和命名空间不翻译；保留百分号格式参数、编号占位符、颜色/格式代码、换行及模组自定义标记。
- 输出必须是合法 JSON，键集合一致、值类型正确；校验占位符数量及必要顺序。失败条目不能悄悄覆盖原文。
- 提供术语一致性检查和人工审阅；AI 可能误解缺少上下文的短词，不能保证全自动翻译质量。
- 不混入贴图、音频、代码或无关文件，读取 JAR 时限制条目路径、数量与解压大小。
- 某些模组使用硬编码文本、脚本或非标准语言系统，这些第一版明确标为不支持。
- 语言资源包通常不能替代启动器模组商店的中文项目名索引；两者是不同功能。

## 推荐顺序
先完成单模组、缺失条目翻译、预览校验和资源包导出。稳定后再考虑多模组批量翻译、术语表共享、模组升级后的增量补译。不要第一版就自动翻译整个整合包。
