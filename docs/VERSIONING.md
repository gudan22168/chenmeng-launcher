# 版本编号与发布

采用 主版本.次版本.补丁，例如 1.0.0。
- 主版本：不兼容的数据格式、配置或使用方式变化，并提供迁移说明。
- 次版本：向后兼容的新功能，例如 1.1.0。
- 补丁：兼容的问题修复与小调整，例如 1.0.1。
- 预发行版：1.1.0-beta.1、1.1.0-rc.1。GitHub 标记为预发行，不设为 Latest。
- Actions 运行编号只是构建编号，不替代应用版本。

package.json 是版本来源，package-lock.json 根版本、界面显示、EXE 文件名和 Git 标签保持一致。
已发布标签不移动、安装包不覆盖；修复后发布新补丁版本。

正式发布：更新两个 package 文件版本，新增 releases/v<版本>.md 后推送 main。Release 工作流测试、构建、生成 SHA256 后发布对应 GitHub Release，并把标签绑定到本次构建的准确提交。
日常没有发布说明变更的提交只运行普通 Windows 构建，不发布 Release。
手动重跑 Release 工作流时必须选择 main；已发布版本不会覆盖。
